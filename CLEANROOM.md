Kaho AI is built from scratch using only public documentation and first-principles engineering.
Note here any public docs or sources relied on for non-obvious decisions.

| 2026-09-28 | Telephony is Plivo, inbound first, via `apps/voice/server.py`: `/answer` returns `<Stream bidirectional="true" contentType="audio/x-mulaw;rate=8000">` pointing at `/ws`, and Pipecat's `PlivoFrameSerializer` converts the 8kHz mu-law to and from PCM and sends `clearAudio` on barge-in. | 2026-09-28 | Call transcripts are stored as text only, through `CallTranscript`, which masks Aadhaar (any 12 digits, last 4 kept) and PAN inside the single `write` method, so no caller can store an unmasked turn. Over-masking is deliberate: a masked phone number costs a follow-up, a stored Aadhaar is a breach. Turns that look like number fragments are held and masked as one run, because a live test showed Deepgram ending a turn at every pause while an Aadhaar was read out (`2 3 4` / `5 6 7` / `8 9 1` / `2 3 4,`), so per-turn masking stored the whole number in pieces. Verified end to end with synthesized speech through `/ws`: no digit or PAN letter reached the file. Known gaps: numbers STT leaves as words, and an STT-misheard PAN letter is still masked (it heard `F` as `S`). Audio is not recorded: consent is undecided. | Observed live in the Plivo smoke test; UIDAI/Income Tax formats (12 digits, `AAAAA9999A`) |
| 2026-09-28 | The post-call summary reads the *masked transcript file*, not the live conversation, so it can only see text that already went through masking; its output is masked again since a model can restate anything. | 2026-09-28 | Provider failure on the call path.
